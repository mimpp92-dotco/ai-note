# src — Next.js 앱 (UI · API · 핵심 계약)

상위 진입점: [../AGENTS.md](../AGENTS.md) · 전체 계약: [../docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md)

## 목적 Purpose / Owns
녹음 UI, HTTP API 라우트, 그리고 프로젝트의 순수 도메인 계약(타입·FSM·zod 스키마)을 소유한다. 교정·요약은 백그라운드 워커가 사용자의 로컬 CLI(claude/codex)·Ollama로 수행한다($0 — API 키 미저장).

- `src/app/` — 페이지(`src/app/page.tsx`, `src/app/meetings/[id]/page.tsx`, `src/app/glossary/page.tsx`, `src/app/settings/page.tsx`) + 앱 셸 `src/app/layout.tsx`(좌측 `LibraryNavigation` rail + skip-to-content + 우측 `ChatPanel` — **현재 dormant: `MEETING_ASSISTANT_ENABLED`(`src/lib/features.ts`, 기본 `false`)가 `true`일 때만 마운트, ADR 0019**) + API 라우트 핸들러(`src/app/api/meetings/route.ts`, `src/app/api/meetings/[id]/title/route.ts`, content read probe와 transcript/summary save·regenerate route, `src/app/api/glossary/route.ts`, `src/app/api/transcribe/route.ts`, `src/app/api/search/route.ts`, `src/app/api/chat/route.ts` 등, 모두 Node 런타임). 회의 삭제는 `meetings/[id]/route.ts`의 `DELETE`. 검색·질문은 별도 `/search` 페이지가 아니라 앱 셸의 오버레이·패널 진입점이다(전용 페이지 없음).
- `src/components/` — app-level native top-layer `AppDialog`/`AppDrawer`(`__tests__/AppDialog.test.tsx`), horizontal controlled `Tabs`(`__tests__/Tabs.test.tsx`), layout-scoped `RecorderSessionProvider`(MediaRecorder/retained Blob/navigation guard)와 `LibraryProvider`(version/freshness/bounded pages), view `Recorder`, `GuardedLink`/`useGuardedRouter`, `HomeClient`, `MeetingList`/`MeetingRow`/`EditableTitle`, `MeetingDetailView`, `GlossaryClient`, 검색·질문 표면(`SearchOverlay`가 shared `useMeetingSearch`+`SearchPanel`과 `SearchResults`를 소유; `ChatPanel`이 hoisted `useChatController`와 `ChatClient`/`ChatAnswer`를 앱 셸 우측에 호스팅), 공유 헬스 훅 `useHealth`(whisper·LLM 폴러 1개, endpoint별 in-flight dedup) 등. `MeetingDetailView`는 title/metadata → notice → action → audio/review → Tabs/panel 순서와 저장 직후 participants copy freshness를 소유한다. `LibraryPrimitives`는 `AppDialog`를 감싸는 `LibraryDialogShell` 하나만 노출한다.
- `src/domain/` — 무의존 타입/FSM/스키마(`src/domain/meeting.ts`, `src/domain/library.ts`, `src/domain/libraryRecoveryIntent.ts`, `src/domain/libraryRecoveryPlanner.ts`, `src/domain/summarySchema.ts`, `src/domain/glossary.ts`). Library structural invariant, runtime `StatusJson`, meeting-record 분류는 `domain/library.ts`가 소유하고 recovery parser/planner는 filesystem을 열지 않는다.
- `src/lib/` — 유틸(`durableFileOps`, `library`, `status`, `meetingLifecycle`, `artifactLease`, `artifactPair`, `audioStream`, `finalizeRecord`, `finalizePlacement`, `pipelineSettings`, `correctionChunks`, `correctionRunner`, `summarizeCheckpoint`, `summarizeCore`, `summarizePublisher`). `audioStream`은 single byte-range 정규화와 Node→Web backpressure/settle-once release를 소유한다. `library.json`은 library repository, `pipeline-settings.json`은 pipeline settings app-api, `glossary.json`은 glossary app-api 단일 writer다. Meeting 내부 `.correction-checkpoint.json`은 summarize coordinator만 읽고 쓴다.
- `src/services/` — 외부 래퍼(`src/services/whisperClient.ts` + LLM 백엔드 `src/services/llm/`: `claudeCli`·`codexCli`·`ollama`·`exec`·`index`(factory)·`types`·`fake`). claude/codex health는 `--version` 바이너리 감지(“감지됨”)이고, 생성 호출은 `LLM_GENERATION_TIMEOUT_MS`(30분/1,800초)로 실행한다. Summary만 generated-summary strict schema option을 사용하고 chat은 generic JSON option을 유지한다. CLI optional flag는 bounded process-level help probe로 generation 전에만 결정하며 generation을 unsupported flag 때문에 재실행하지 않는다. Claude는 OAuth를 보존하는 temp cwd/MCP·slash·tools/session-off와 `$0` env scrub, Codex는 supported ephemeral/read-only temp isolation을 적용하고 Ollama는 schema object를 `format`으로 보낸다(ADR 0010, 0024).

## 자주 하는 변경 Common changes (patterns)
- **새 API 라우트**: `src/app/api/**/route.ts`에 추가. **주의(build-green)**: `data/`를 읽으면 `export const dynamic='force-dynamic'` + fetch는 `cache:'no-store'`; top-level `process.env` 접근 금지(핸들러 내 지연); edge 런타임 금지.
- **Data surface**: 새 route/RSC를 `DATA_SURFACE_INVENTORY`에 등록하고 첫 side effect 전에 `guardLocalApiRequest()`/page guard를 호출한다. JSON은 `parseBoundedJsonBody()`, status 응답은 `toPublicMeeting*()`, 오류는 static `publicErrorResponse()`를 사용한다. Internal `StatusJson` spread, path/job/attempt/raw Error 응답·로그 금지.
- **상태 전이**: `status.json`은 **app-api만** 쓴다(단일 writer). FSM은 `src/domain/meeting.ts` 참조.
- **삭제 fence**: `meetingTombstone.ts`만 tombstone을 쓰고 `meetingCleanup.ts`가 placement/live directory/deterministic trash를 재시도한다. ID를 다루는 새 read/write surface는 body/fs 전 `meetingFenceResponse()`를 호출하고, status updater 방어를 우회하지 말 것.
- **Finalize 발행**: `finalizeRecord.ts`만 hidden intent/audio/status/receipt를 만들고 canonical meeting directory를 publish한다. Body 전 intent, operation→artifact lease, receipt-only final invariant를 지킨다. `finalizePlacement.ts`는 latest canonical placement를 우선하며 pending/unavailable record를 generic reconcile에 먼저 materialize하지 말 것.
- **Recorder/session navigation**: route component에서 MediaRecorder/Blob을 소유하지 않는다. `RecorderSessionProvider`가 stable ID, start 시점 canonical location snapshot, retained Blob과 finalize metadata를 layout lifetime으로 보존한다. Ambiguous upload는 bodyless same-ID probe가 `body_required|not_committed`를 확인하기 전 재전송하지 않는다. 같은 provider의 bounded navigation-blocker registry가 dirty/saving/verifying transcript·summary editor도 소유한다. 모든 client navigation surface는 `GuardedLink` 또는 `useGuardedRouter`를 사용하고 same-path query 이동 외에는 확인된 explicit discard 없이 unsaved audio/content를 잃게 만들지 말 것. Saving/verifying에는 discard를 허용하지 않고 판정 뒤 pending navigation을 재평가한다.
- **Modal/drawer surface**: 새 modal은 fixed/z-index/document key listener를 만들지 말고 `AppDialog`/`AppDrawer`를 사용한다. Feature가 initial focus와 success destination을 선택하고 primitive가 native cancel/backdrop, user-dismiss focus return, nested ref-count body scroll lock을 맡는다. Mutation 중에는 `dismissible=false`와 실제 disabled cancel을 함께 적용한다.
- **Library client data**: `LibraryProvider`만 organization version/scope/page window와 summary-work/organization-pending freshness를 소유한다. Higher/lower revision 규칙, mutation/resource operation epoch, endpoint별 abort를 우회해 component local cache를 만들지 않는다. `libraryClient.ts`의 max 5 pages/500 entities와 canonical URL resolver를 재사용한다. Health는 기존 singleton hook을 계속 사용한다.
- **Library move**: Meeting 이동은 `PATCH /api/meetings/[id]/location`, folder reparent는 분리된 `PATCH /api/folders/[id]/parent`만 사용한다. Pure reducer post-condition과 expected generation+revision, latest live scan, destination strictness를 우회하지 않는다. Artifact path를 바꾸거나 stale destination을 fallback하지 말고 existing user placement가 finalize receipt보다 우선한다.
- **Preservation container delete**: Folder/workspace delete는 preview와 commit을 분리하고 `libraryContainerDelete` pure calculator/reducer를 둘 다 사용한다. Commit은 latest scan+pending receipt를 queue 안에서 다시 계산한다. Folder는 direct placement rehome+child promote, workspace는 destination unfiled rehome+default transition이며 meeting directory/artifact나 immutable finalize receipt를 삭제·rewrite하지 않는다.
- **Recovery planner/executor 분리**: `libraryRecoveryIntent`는 path 없는 strict semantic intent와 recoveryId-derived basename만 정의하고, `libraryRecoveryPlanner`는 typed observation을 pure decision으로 바꾼다. `libraryRecoveryExecutor`만 같은 library queue에서 private archive/publish/restore side effect를 수행한다. Intent phase는 atomic replace하고 unsafe/multiple/mismatch/unknown state를 cleanup/bootstrap으로 낮추지 않는다. `/api/library/rebuild`는 corrupt fingerprint 외 path/name/recoveryId를 받지 않는다(ADR 0017).
- **Activated library UI**: `LibraryNavigation`은 desktop rail/native top-layer mobile drawer와 workspace/folder create/edit·same-workspace folder move·preservation delete를 소유한다. Native workspace `<select>`와 aria-hidden chevron, folder disclosure/scope/edit/create의 독립 44px target을 같은 navigation markup에서 유지하고, interactive kebab/chevron/plus/menu/close는 `InlineIcons.tsx`의 shared SVG만 쓴다. `HomeClient`는 canonical scope와 provider page, 16px→24px gutter, banner/empty-state reflow를 렌더하고 queryless legacy list를 count source로 쓰지 않는다. `MeetingRow`/`EditableTitle`은 card 밖 kebab, `w-full min-w-0` long-content ownership, mobile stacked edit/delete, IME-safe Enter와 실패 focus 보존을 소유한다. `LibraryLocationPicker`는 meeting cross-workspace와 folder same-workspace intent를 구분하고 `ContainerDeleteDialog`는 preview token/name confirmation/IME guard를 소유한다. Scoped detail은 `detailSource.ts`의 structured IDs만 검증하며 raw `returnTo`/client names를 사용하지 않는다. Ready/last-good scope recorder는 immutable ID destination을 전달하고 global fallback만 no-location으로 시작한다. `LibraryRecoveryPanel`은 corrupt-only rebuild, recorder Blob gate, exact IME confirmation을 소유하고 success는 provider generation reset 뒤 new default All로 이동한다.
- **Detail/Tabs/review/content edit**: `Tabs.tsx`는 horizontal few-tab ARIA relationships와 Left/Right wrap·Home/End automatic activation만 소유하고 feature data를 갖지 않는다. Global `회의 작업`은 이동·폴더 열기·combined Markdown만 둔다. 선택 panel의 첫 content group은 tab-local action bar이며 transcript는 copy/edit/raw 재생성, summary는 copy/JSON/edit/current-transcript 재생성 순서로 warning과 body보다 앞선다. Editor는 읽기 body를 single textarea로 교체하고 동시에 렌더하지 않는다. Summary는 `summaryBodyFromSummary()`의 deterministic projection 또는 existing manual `body`를 그대로 편집하며 title/topicSlug/participants를 포함하거나 heading/action item을 parse하지 않는다. 수동 저장은 stable full-pair revision을 요구하고 network/invalid-2xx 뒤 PATCH를 blind retry하지 않고 `GET /content` probe로 intended/predecessor/third revision을 판정한다. Transcript 변경은 기존 summary를 보존한 채 outdated로 만들며 summary 저장/재생성만 current transcript 기준 fresh로 만든다. Copy/download는 열린 draft가 아닌 confirmed content를 사용하고 action status가 이를 알린다. Title은 title route, 참석자는 review route의 전용 writer를 계속 사용한다. Detail utility sibling은 같은 44px rectangular group이며 audio/review가 tabs 앞에 온다. Review success body를 검증해 local current participants를 갱신하되 dirty input은 parent refresh로 덮지 않는다. Component 회귀는 `components/__tests__/Tabs.test.tsx`, `MeetingContentEditors.test.tsx`, `views.test.tsx`에 둔다.
- **검색·질문 표면**: 검색·질문은 `/search` 페이지가 아니라 앱 셸 진입점이다. 검색은 `LibraryNavigation`의 돋보기 트리거가 여는 shared `SearchOverlay`(native `AppDialog`), 질문은 `ChatPanel`(desktop 우측 `<aside>` · mobile `AppDrawer`)이다. **질문(`ChatPanel`)은 현재 dormant(flag-gated)**: `layout.tsx`가 `MEETING_ASSISTANT_ENABLED`(기본 `false`)일 때만 마운트하며 코드·`/api/chat`·테스트·공유 지식 인덱스는 보존한다(ADR 0019, revive=flag를 `true`로). 검색 표면과 `GET /api/search`는 이 flag와 무관하게 계속 동작한다. `ChatPanel`은 `useChatController`를 hoist해 collapse/expand·drawer 사이에 대화/초안을 보존하고, 답변의 검색 액션(`onSearchReplay`/`onSwitchToSearch`)은 router push가 아니라 같은 `SearchOverlay`를 연다. `searchReplay`는 `SearchOverlay`의 `initialReplay` prop으로 열림 시 once-per-open 재생한다. Chat 계약(`/api/chat`)은 `chatOrchestrator.ts`가 소유하며 `extractJsonObject`로 코드블록/wrapper JSON을 salvage하고, discovery 전용 `search_transcripts`(`transcriptSearch.ts`)는 citation credit 없이 전사 후보만 찾는다. 단순 `GET /api/search`와 `useMeetingSearch`/`SearchPanel` 동작·계약은 이 배치로 바뀌지 않는다. 회귀는 `components/__tests__/ChatPanel.test.tsx`(오버레이 진입)·`ChatClient.test.tsx`·`SearchOverlay.test.tsx`에 둔다.
- **목록·상세 content generation inflight**: durable `status.summarizeAttempt` kind를 public `contentOperation:initial|transcript|summary|null`로 투영한다. `initial`/legacy `resummarize`/`summary_regenerate`와 `transcript_regenerate`를 구분해 목록·상세가 각각 `회의록 요약 생성 중`/`전체 스크립트 생성 중`을 표시하며 `manual_edit`는 생성 중으로 투영하지 않는다. Legacy `resummarizeInflight`는 summary 계열 호환 신호일 뿐 새 분기의 정본이 아니다. `deriveStatus`/FSM enum은 건드리지 않는 표시용 projection이다.
- **Glossary/Settings form state**: Initial GET은 `loading|ready|load_error`를 구분하고 non-2xx/network/invalid body를 empty/default로 낮추지 않는다. Retry/unmount는 이전 GET을 abort하고 load error에서는 replace-style save를 노출하지 않는다. Glossary는 shared `Tabs`와 explicit dirty save를 사용하고, Settings는 server-confirmed snapshot과 normalized draft를 분리해 dirty일 때 connection test를 막는다. Settings health는 persisted configuration만 검사하며 결과 context에 provider/model만 쓰고 baseUrl은 노출하지 않는다.
- **First-use summary readiness**: `useHealth`의 LLM state가 loading/ready가 아니면 Home은 recorder 앞에 비차단 readiness card를 둔다. Primary는 설정, secondary는 같은 화면의 `#meeting-recorder-start`로 scroll+focus하며 녹음·로컬 전사를 막지 않는다. 설정 page는 요약 모델을 optional profile보다 먼저 렌더하고 profile 미설정은 녹음·전사·일반 검색을 막지 않는다고 설명한다. 첫 전사는 선택 Whisper model download로 오래 걸릴 수 있으며 download 전 가짜 progress를 만들지 않는다.
- **Pipeline settings**: `data/pipeline-settings.json`의 strict atomic document 하나에 `large-v3|large-v3-turbo`와 `full|fast`를 함께 저장한다. Missing/legacy는 `large-v3`+`full`; fast는 실험적 opt-in이다. 저장은 model prepare/download를 호출하지 않으며 **선택 모델 미리 준비**가 별도 endpoint를 호출한다. 임의 Whisper repo/path/model 문자열 UI를 만들거나 benchmark 전 Turbo/fast를 권장하지 않는다.
- **Fast correction·checkpoint**: immutable raw/segments natural boundary 기반 plan만 사용하고 read-only context는 model output/merge에 넣지 않는다. Claude/Codex 동시성 2, Ollama 1을 넘지 않으며 chunk validation/commit 뒤 source order로만 merge한다. 첫 실패 뒤 새 chunk나 full fallback을 시작하지 않는다. Full/fast checkpoint key가 exact match할 때 수동 retry만 교정 또는 completed chunk를 재사용하고 summary는 모든 chunk가 valid한 뒤 한 번만 호출한다. Pair publication 성공 전 checkpoint를 삭제하지 않는다.
- **Provider-aware model selector**: Claude는 empty CLI default/`sonnet|opus|haiku`/custom, Codex는 empty CLI default/custom만 제공한다. Ollama는 current draft의 explicit-port loopback base URL로 `POST /api/settings/llm/models`를 호출해 설치된 model만 select에 넣고 refresh/custom을 제공하며 pull이나 remote catalog를 호출하지 않는다. Unknown stored string은 custom draft로 exact 보존하고 전송 직전 trim한다. Provider별 draft는 session 동안 분리하며 save는 current provider의 model, Ollama일 때만 baseUrl을 보낸다. Save success body를 persisted snapshot으로 반영한 직후 그 snapshot의 health를 자동 검사한다. CLI ok는 binary 감지(인증/생성 보장 아님), Ollama ok는 selected installed model 연결 확인이다.
- **Transcription failure/retry UI**: `retry_transcription`은 목록에서 일반 transcribing 대신 `전사 실패`, 상세와 finalize result에서 safe failure+`전사 다시 시도`를 유지한다. 두 retry는 exact meeting ID로 기존 `POST /api/transcribe {id}`를 호출하고 accepted/409 race 뒤 server state를 다시 읽는다. 요청 중 disable label과 polite status를 제공하고 완료 뒤 trigger focus를 복구한다. Detail polling은 single in-flight이며 unmount/navigation/status change에서 abort/cleanup하고 client timeout을 persisted 전사 실패로 만들지 않는다. 새 endpoint/dispatch를 만들거나 artifact를 직접 수정하지 않는다.
- **실패 재시작 경계**: finalize 뒤 최초 transcription/summarize dispatch만 자동이다. `retry_transcription`, `retry_summary`, fast chunk failure 같은 명시적 실패는 worker poll, network 복귀, app restart가 새 attempt로 재실행하지 않으며 사용자의 기존 manual retry surface만 다시 시작한다. Supervisor restart/autostart, stale watchdog, pipeline-stage progress UI를 추가하지 않는다.
- **Meeting detail initial tab**: explicit `contentTab=script|summary`가 최우선이다. Query가 없고 usable summary가 있으면 `회의록 요약`, 없으면 `전체 스크립트`를 초기 tab으로 사용한다.
- **Recorder live announcements**: Full/compact recorder의 timer·meter·action subtree를 live region으로 감싸지 않는다. `recorderPhaseAnnouncement()`의 dedicated polite status만 lifecycle phase 전환을 알리고 시각 timer/meter semantics는 그대로 유지한다.
- **Audio read route**: `api/meetings/[id]/audio/route.ts`는 guard/fence/read-lease 순서를 유지한 채 no-range `200`, single range `206`, invalid/empty `416` headers를 조립한다. `lib/audioStream.ts`만 range normalization과 abort/cancel/end/close/error release-once adapter를 소유한다. Route bytes/headers는 `api/__tests__/routes.integration.test.ts`, cancel/abort race는 `api/__tests__/audioStream.test.ts`, tombstone ordering은 `api/__tests__/tombstoneFence.test.ts`에서 검증한다.
- **아티팩트 쓰기**: 항상 `src/lib/atomicWrite.ts` 또는 정책을 노출하는 `src/lib/durableFileOps.ts`(temp→file fsync→rename→parent fsync) 경유. rename 이후 sync 실패는 committed/pending으로 처리하며 원본(`audio.webm`/`raw.md`/`segments.json`)은 수정 금지. API/UI/LLM adapter는 canonical transcript/summary를 직접 쓰지 않고 수동 저장과 독립 생성도 모두 pair publisher를 거친다.
- **Library registry**: `src/lib/library.ts`만 `data/library.json`을 쓴다. absolute-path process queue, `libraryId+revision`, read mode, bootstrap/reconcile/last-good 계약을 우회하지 않는다. 모든 scanner는 typed observation을 만든 뒤 `classifyMeetingRecord()`를 정확히 한 번 호출한다.
- **콘텐츠 생성/발행**: 최초 `initial`만 immutable raw correction 뒤 그 transcript로 summary를 만든다. `transcript_regenerate`는 raw+glossary correction 한 번만 호출하고 summary bytes/revision metadata를 보존하며 index를 갱신하지 않는다. `summary_regenerate`는 current canonical transcript만 요약하고 correction/raw를 읽지 않으며 성공 뒤 index를 best-effort 갱신한다. `manual_edit`은 LLM을 호출하지 않는다. 모든 경로는 unchanged opposite artifact까지 포함한 full pair를 `summarizePublisher.ts`로 내구 staging·발행하고 `contentRevision` hash/source/base 관계를 함께 commit한다. 상세/export는 `readArtifactPair()`, 폴더 삭제/cleanup은 operation owner로 artifact write lease를 잡은 뒤 수행한다. Pair read lease 안에서 status/library를 mutation하지 말 것(ADR 0013, 0021).
- **Summary body/consumer**: Legacy body-less structured summary는 migration 없이 읽는다. Optional `body`가 있으면 whitespace-only를 거부하고 structured editable fields를 모두 비워 dual truth를 금지한다. Manual save는 CRLF만 LF로 바꾼 exact body와 preserved title/topicSlug/participants를 full pair publisher에 전달한다. Detail/copy/Markdown/JSON/knowledge/search/chat은 body를 current summary content로 사용한다. Knowledge corpus body는 4,000 characters로 bounded하고 일반 검색은 weight 85의 `회의록 본문` field를 제공하지만 body에서 action item/owner/due/participants를 추론하지 않는다. Outdated card/body는 semantic search나 chat citation evidence로 쓰지 않는다(ADR 0022).
